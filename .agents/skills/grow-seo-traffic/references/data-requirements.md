# 数据需求与充分性

## 数据清单模板

在目标项目创建或更新 `docs/grow-seo-traffic/data-checklist.md`：

```markdown
# SEO 数据清单

- 分析目标：
- 目标站点：
- 目标市场与语言：
- 清单更新时间：
- 当前结论：数据充足 / 数据不足

| 数据项 | 为什么需要 | 建议范围 | 获取方式/授权 | 当前状态 | 来源与保存位置 | 备注 |
|--------|------------|----------|---------------|----------|----------------|------|
| 第一方搜索表现 | 建立真实基线 | 最近 3 个月，至少 28 天 | 用户提供 / Agent 代取 | missing | | |
```

状态只使用：

- `ready`：资料已阅读，口径和关键内容足以支撑当前判断；
- `partial-ready`：资料已阅读，足以支撑某个子判断，但仍缺少会影响完整结论的数据；输出时必须明确限制；
- `missing`：尚未获得；
- `unclear`：已经获得，但范围、过滤条件或内容看不清；
- `unavailable`：用户确认暂时无法提供。

清单要覆盖全部需求，但向用户追问时优先询问最关键的 1–3 项。

“获取方式/授权”记录用户上传、公开网页、连接器/API、Computer Use 或 `$xai-call-grok`，以及是否已经
允许 Agent 使用登录会话。授权状态不清时先询问，不假设可以操作用户浏览器。

Semrush 数据通过代理获取时，来源栏同时记录 `Semrush` 和实际代理 URL，避免把代理误当成独立数据源。

## 所有 SEO 优化都需要

### 1. 项目目标

- 目标站点；
- 主要产品或服务；
- 目标市场与语言；
- 最重要的业务目标或页面；
- 本次想解决的问题和允许修改的范围。

这些信息可以从当前项目和对话中获得，不明确时再询问用户。

### 2. 当前项目与线上页面

Agent 直接检查：

- 代码、路由和页面类型；
- title、description、H1、canonical、hreflang；
- robots、sitemap、noindex；
- 结构化数据和内部链接；
- 核心工具或产品体验；
- 已上线内容与目标搜索意图。

项目无法运行或线上地址不明确时向用户询问。

### 3. 实时搜索结果

针对候选查询检查当前 SERP、结果类型、排名页面和真实竞品。此项通常由 Agent 通过网页搜索获取，不必要求用户导出。
如果用户明确要求竞品调查、SERP 截图或查看前排竞品关键词，实时 SERP 还必须包含截图/文本保存、广告与自然结果边界、前排页面 URL 表，以及后续 Semrush 竞品反查结果；只有关键词工具数据而没有实时 SERP 不足以判断当前搜索意图。

## 已有站点需要

### 第一方搜索表现

优先使用 Google Search Console、Bing Webmaster Tools 或等价第一方平台。建议最近 3 个月，最低 28 天，并尽量包含：

- 日期趋势；
- 查询；
- 页面；
- 点击；
- 展示；
- CTR；
- 平均排名；
- 国家、设备、搜索类型和其他过滤条件。

如果网站流量很低，可以用更长周期。只有总览截图但看不到查询和页面时，通常不足以制定页面级优化。

## 新站或尚无搜索数据

先确认站点确实没有历史数据，而不是仅仅没有取得权限。此时不要求虚构第一方基线，但必须具备：

- 项目目标、产品能力、目标市场和语言；
- 当前代码或可检查的页面；
- 目标主题的关键词需求证据；
- 实时 SERP、结果类型和竞品页面；
- robots、sitemap、metadata、canonical、结构化数据和内部链接检查；
- 上线后准备采集的 GSC/Bing 基线与复查时间。

报告中明确标记为“新站研究与上线前优化”，不要声称已经由历史流量验证。

## 按任务追加的数据

### 流量、排名或 CTR

必需：

- 第一方日期、查询和页面数据；
- 至少 28 天；
- 当前项目和线上页面。

如果缺少查询或页面维度，只能描述总体趋势，不能据此修改具体页面。

### 索引与抓取

必需：

- GSC Page Indexing、URL Inspection、Bing Index Explorer 或等价第一方索引信息；
- sitemap 状态；
- robots、canonical、noindex 和实际 HTTP 响应；
- 示例 URL 和检查日期。

搜索表现不能替代索引数据。

### 内容与关键词机会

必需：

- 已有站点需要第一方搜索表现；新站需要关键词需求证据；
- 当前页面与内容清单；
- 实时 SERP；如果涉及竞品机会，需包含 SERP 前排页面与竞品关键词反查。

建议补充：

- Semrush、Ahrefs、Keyword Planner、Google Trends 或等价需求数据；
- 真实竞品页面；
- X 平台上围绕目标关键词、用户问题和竞品的近期讨论；
- 目标市场、语言、设备和数据日期。

如果任务要求“关键词机会”“长尾词”“内容扩张”或“新页面机会”，第三方关键词工具数据不能只包含目标站点的
Organic Positions / Top Pages。至少需要 Keyword Overview、Keyword Magic、Keyword Planner、Ahrefs
Keywords Explorer 或等价数据中的一种，能看到 seed 词和长尾变体的搜索量、难度、意图和问题词。否则只能做
已有页面/已有排名分析，不能输出完整关键词机会池。

没有第三方工具数据时，已有站点仍可基于第一方查询和实时 SERP 分析，但必须降低搜索量与竞争度判断的置信度。
X 讨论是近期语言和痛点信号，不是搜索量，也不能单独证明值得创建页面。

### 实验复查

必需：

- 具体改动、页面范围和上线日期；
- 上线前基线；
- 上线后观察数据；
- 同一个第一方来源覆盖完整前后窗口；
- 必要时的索引状态。

不同搜索引擎不能拼接成一个实验窗口。

## 格式与可读性

不限制格式。用户可以提供：

- 任意导出文件或电子表格；
- 截图、PDF 或录屏；
- 粘贴的表格和文本；
- API 返回或数据库查询结果；
- 公开或需登录的链接；
- 已登录浏览器会话；
- 其他 Agent 能可靠理解的资料。

格式不限不等于内容不限。资料必须能看清当前判断所需的时间范围、维度、关键数字和过滤条件。看不清时标记 `unclear` 并具体说明还需要什么。

## 数据充足的判断

只有同时满足以下条件才进入分析：

1. 当前任务的必需数据项全部为 `ready`；若为 `partial-ready`，只能进入与已满足数据对应的有限分析范围；
2. 已逐份读取资料，而不是只看文件名；
3. 时间范围、市场、设备和过滤条件足够明确；
4. 已有站点的第一方数据能够支撑页面或查询层面的判断；新站已经确认没有历史数据并具备需求与 SERP 证据；
5. 当前项目和线上页面已经检查；
6. 没有仍可能明显改变优先级的关键缺口。

对于已有站点，第三方估算、经验判断和竞品数据不能替代缺失的第一方站点数据。
