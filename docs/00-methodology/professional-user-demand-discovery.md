# 面向工作用途用户的需求发现方法

日期：2026-09-10。用户当前希望暂停 VocalDock 讨论，探索图片生成或其他垂直方向，先讨论方法论。目标暂理解为利用工具赚钱或提高工作效率、具有采购能力的个人和小团队，而非泛指所有在职人员。本轮仅核查来源及整理方法，没有完成具体赛道验证。

## 核心顺序

人群 → 正在发生的付费任务 → 现有做法与缺口 → 验收标准 → 可触达渠道 → 小规模真实交付 → 软件。

“能省时间”不是充分的付费条件，还要知道谁承担成本、谁能决定付款、节省的时间是否有价值，以及更换工具的成本。使用者与付款者分开记录。

## 来源分工

| 来源 | 用途 | 限制 |
| --- | --- | --- |
| 收入榜单 | 找已出现收入的产品，反查客户及商业模式 | 收入不是利润；公开样本有选择偏差，不能证明我们能复制渠道 |
| 外包任务、服务成交反馈 | 找已有预算、交付要求和反复发生的任务 | 服务上架与报价是供给证据，不是成交；雇人可能是为了审美、沟通和责任而非机械操作 |
| 垂直社区、竞品评论 | 找工作步骤、迁移理由、反复出现的失败 | 抱怨不等于购买；需区分用户角色，去重并核查时效 |
| 招聘描述、实际教程 | 找重复劳动和工具拼接 | 岗位预算不等于软件预算，复杂任务未必适合自动化 |
| 客户实际任务与付费试用 | 判断结果是否可用、是否替换现有开支 | 试用补贴、朋友订单不能代表可持续购买 |

## 图片方向的研究单位

研究“谁为什么交付哪种图片”，不以“AI 图片生成器”作为需求单位。候选例子仅供搜集证据：频繁上新的二手卖家、替商家交付素材的工作室、制作多版本广告的运营人员。

对每个候选，记录过去一次任务的输入、数量、截止日期、原有工具/外包支出、人工校对时间、返工原因、最终验收人，以及在哪里能接触第二批同类用户。

图片类重点是每张最终合格图片的总成本：生成失败、重试、人工修正和审核均计入。商品外观、文字和品牌一致性等要求需由目标客户确认，不能把“看起来漂亮”当成验收标准。

## 起步研究范围（建议预算，非验证门槛）

选择三类人群，每类收集约十条去重的真实任务线索。只对证据最强的一类做进一步了解，争取观察三至五个不同用户的近期完整任务。数量仅用于限制研究范围，不代表统计验证。

优先级：已花钱解决、任务重复、验收明确、付款人可触达、现有方案有具体缺口、能承担交付成本。缺少其中关键证据时标记未知，不用打分掩盖空白。

先使用现有工具交付真实任务，记录验收、净节省时间、实际付款与再次委托；确认这些之后再产品化。当前没有对外联系或收费授权，本轮未执行外联。

## 本轮核查来源

- [TrustMRR](https://trustmrr.com/)：页面展示收入榜及交易市场，适合作为候选产品入口；本轮未审计其各家收入或利润。
- [Upwork 图片编辑服务目录](https://www.upwork.com/services/photoshop-editing)：存在修图、背景处理等服务分类，目录不能单独证明具体需求的成交规模。
- [Upwork 商品图服务示例](https://www.upwork.com/services/product/design-edited-e-commerce-product-photos-and-background-removal-2071590532596113181)：展示批量商品图及平台交付需求，属于服务方描述，不是已核验成交。
- [Reddit：Photoroom 使用讨论](https://www.reddit.com/r/photoroom/comments/1uccdum/photoroom_is_a_tool_not_a_magic_wand/)：发帖者自述用于多个二手平台销售，作为用户场景线索，不推算行业规模。
- [Reddit：Photoroom 套餐抱怨](https://www.reddit.com/r/Flipping/comments/1opjagi/do_not_get_a_photoroom_plan_terrible/)：用于研究批量使用者的价格及额度困扰；用户说法不等于当前官方价格或已验证事实。
