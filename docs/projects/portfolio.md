- 讨论新项目之前，先看这份档案。用户已经有上线、获取流量和获得订单的经验，不应继续默认其没有项目或没有现成流量。

- 收到更新时，先在 `records/` 中追加带日期的记录，再更新本页对应项目；保留历史口径和来源。
- 分开记录流量、使用、订单、收入、成本和净利润。没有金额时，不用订单数推算收入；有订单不等于已经盈利。
- 用户判断、原始数值、待确认口径与讨论建议分别标记，不把建议记录为已决定执行的计划。

## 后续讨论的共同背景

以下是记录使用上的约束，不是已完成的数据分析：

1. 用户的项目组合中，已经同时存在“有流量但未变现”“有订单但成本与转化有压力”“聚焦改版后刚出首单”和“新上线、待推广”的情况。
2. 后续讨论“先做流量还是先做变现”时，应引用对应项目的实际状态，避免把不同项目的流量和订单混为同一个转化漏斗。
3. 是否优先优化现有站、投入某一个站或继续做新站，用户尚未作出决定；本档案不设定资源分配优先级。
4. 现有站点之间是否适合导流，尚未验证人群和任务是否重合；不能只因同属用户所有就认定可以交叉转化。
5. 本次没有修改线上产品、免费额度、价格、广告配置或推广计划。
