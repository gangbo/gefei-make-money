# 图片自动化：已有产品与边界实验

日期：2026-09-10。承接[首轮需求研究](../../02-candidates/reviews/image-work-demand-research-2026-09-10.md)。本轮目标：判断可标准化的图片任务是否值得继续验证，而非上线产品或承诺收入。

## 结论

固定素材、固定模板、字段替换和多尺寸输出可以程序化，已有成熟产品覆盖。当前证据不足以支持开发一个通用广告变体生成器；此前广告方向的优先级，应限定为继续调查实际工作流程，不是直接开发。

尚未证明的是：用户是否愿意把现有工作迁移给我们，以及无人修图时，真实商品、长文案、品牌规范能否稳定交付。招聘预算不能直接换算成软件收入。

## 实际做了什么

### 公共产品演示

在用户授权的 Chrome 中访问 Bannerbear 图片 API 页面。保留城市与照片默认预设，将文案改为下拉菜单中最长的一项，点击生成。按钮经过等待恢复可用，出现生成图片。演示只提供预设选项，不能据此测试任意用户输入；截图只覆盖部分成图，不能计为完整质量验收。后续浏览器返回 `noWindowsAvailable`，因此未继续做更多用例。未创建账户、购买套餐或上传用户素材。

### 本地合成输入实验

用 Python/Pillow 制作规则模板：标题区、原始几何商品占位区、价格和行动文案。6 组人为构造输入 × 3 个尺寸（1080×1080、1080×1350、1080×1920），共 18 次处理。输入包括短文案、长文案、宽字母、无空格文本、极长文案、非法价格。

- 12 次生成文件；6 次拒绝，其中极长文案和非法价格各 3 次。
- 人工查看[总览图](../experiments/template-layout-2026-09-10/contact-sheet.png)：文字和价格区域未见明显互相覆盖，但逐字符换行会把英文单词拆开；长画幅的占位区域也缺少设计变化。**生成文件不等于可交付。**
- 这些问题中的英文断词可通过词级换行规则修复，不是 AI 能力上限；多尺寸构图则需要模板设计和验收规范。实验没有进一步包装成产品。
- 没有真实商品图、没有 AI 调用、没有客户验收，因此没有测出商品保真率、真实任务通过率、模型重试成本或客户节省时间。12/18 不是商业成功率。

复现：[脚本](../experiments/template-layout-2026-09-10/test_render.py)、[逐项结果](../experiments/template-layout-2026-09-10/results.json)。脚本依赖 Pillow 和 macOS Arial 字体。

## 下一步应如何筛选机会

目前先不开发通用模板工具。转而验证一个假设：已有设计规范的电商运营团队，在价格/优惠频繁变化时，是否仍需人工逐张更新、校对和整理渠道素材。

这只是待验证假设：Abyssale 等已经覆盖商品数据与促销自动化，不能把“表格转促销图”直接当作缺口。必须找到他们用现有工具仍不能完成、或配置维护成本过高的具体原因。

下一轮从 3–5 位有近期实际工作记录的用户取得自愿提供的脱敏任务：原素材、最终交付、修改记录、尺寸规范和耗时。先比较现有工具，再决定是否自己开发。不要让用户只回答“会不会用”。

同一批任务应记录：用户准备输入时间、首次可交付数量、人工修正分钟数、失败原因、处理和重试成本，以及是否需要开发者逐单介入。样本少时只作方向判断。

继续条件建议：多位独立用户反复遇到相同缺口；使用现有工具后仍有明确耗时；他们愿意拿下一批真实任务做付费试用。若现有产品已足够，或每单都需要我们修图和沟通，则停止该候选，不因已经研究过就继续投入。

本轮没有联系他人、收费、发布站点或修改现有生产产品。
