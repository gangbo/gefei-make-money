MRR只是平台快照，不证明持续盈利。Formsquash、Rowform、Bidcraftr反例说明同样清晰的任务与可用技术也可能没有可观收入，不是对类别的否定。

## D-020拟比较的最小工作链（研究范围，不是MVP批准）

一个建站者管理数个客户网站：接入表单→收到消息→确认保存/通知→分配客户→检查失败→交接。比“AI自动回复”更优先研究漏单与多站管理。此细分是我们的假设，现有资料尚未证明该群体在竞品收入中占比。

可以自行用测试站和虚构询盘构造输入；验收可看收件是否准确、是否重复、记录能否找回。成本较PSD兼容更容易拆分是工程判断，不是已测成本。邮件滥用、误拦和投递质量是持续服务工作，不能承诺一天完成生产产品。

## 下一步，不继续无边界找榜单

先对Static Forms和Web3Forms的公开文档做多站交付对照，明确免费/付费边界、交接、失败记录、迁移方式；随后找公开开发者反馈和实际可进入的模板/教程渠道。只完成这条工作链对照，不做通用拖拽表单编辑器或CRM。

建立一个渠道证据表：页面/集成确实存在、第三方实际使用/推荐、流量数据、转化数据分别记。已有博客不是获客已验证。若核心获客只能依赖尚不存在的受众或大量人工销售，降低优先级，保留资料。

AI能写表单代码不代表能代替长期接收/送达服务；这只是值得验证的收费逻辑，不是用户必付费的结论。是否加入AI待核心流程和成本清楚后再决定。
