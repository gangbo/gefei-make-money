# 需求证据卡模板

> 每个具体用户任务一张卡。用户原话、可观察行为、推断与建议分开填写。未获取的信息写“未知”，不要用估计补成事实。

## 基本信息

- 候选 ID（D-xxx）：
- 来源 ID（S-xxx）及已保存资料路径：
- 当前阶段 / 状态：
- 最新决策记录编号：

- 记录日期：
- 关联项目：
- 用户类型（使用者 / 付款者）：
- 触发场景及要完成的结果：
- 证据来源或匿名访谈编号：
- 发生日期与频率：

## 已经发生的行为

- 最近一次完整处理过程：
- 现有软件、人工服务或替代方案：
- 已经付出的金钱、时间与失败成本：
- 付款 / 未付款 / 退款的具体原因：
- 结果用在哪里，后续还有哪些操作：
- 重复使用或下一次任务的证据：
- 同类问题的独立来源数（去除转帖与重复用户）：

## 我们的假设

- 想改善的一个步骤：
- 为什么现有方案没有满足：
- 可以接触这类用户的渠道：
- 有代表性的输入如何自行取得：
- 输出质量如何自行判断，是否依赖逐单人工服务：
- 收费对象与方式：
- 预计交付、支持、获客成本（标明假设）：
- 支持证据：
- 反对证据及其他可能解释：

## 下一次最小实验

- 本次只验证的问题：
- 交付内容、价格及时间：
- 真实样品或演示安排：
- 触达样本与时间 / 成本预算：
- 要观察的任务完成、付款、退款、复用指标：
- 继续 / 调整 / 停止的条件：
- 实际结果：
- 更新日期与下一步：

填写完成并不代表机会已验证；结论取决于证据。任何对外消息、收费实验或线上改动需另按用户实际授权执行。
