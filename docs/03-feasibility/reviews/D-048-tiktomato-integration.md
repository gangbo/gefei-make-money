# D-048：先作为TikTomato站内工具验证

2026-09-15 / DEC-049。用户要求评估，并非开发/上线指令。依据[S-064](../../01-sources/competitors/2026-09-15/hairstyle-tiktomato-fit.md)。

结论：建议先加在TikTomato同域名的独立工具页（拟议/hairstyle），复用账户、积分、上传、异步生成、结果下载。当前无需单独新品牌、新后端或新App。是承载方式选择，不代表已验证应立即开发。

## 为什么适合共用

现有image_generate已接收参考图和编辑描述，发型功能可以采用明确的选项、固定提示规则与单人照片校验。支付、账本和任务保存已有。核心新增工作是发型选择/自拍要求、身份保持质量、对比交互和独立统计，不需要重造SaaS基础。实际集成仍要核对最近代码和接口，未作工期承诺。

当前首页聚焦老照片，发型用户并非同一人群；保留首页核心诉求，通过导航/独立页面承接发型用途。宣传直接指向工具页，避免先进入老照片页面再寻找。这个安排是产品路径判断，不是SEO排名收益预测。

## 有限首版建议

手机网页上传一张单人自拍→选择6–8种发型与少量发色→清楚显示本次消耗→生成一个结果→原图对比/下载。6–8是范围建议，不是需求数据。允许逐个再试，首版不默认一次生成大量图片。不做颜值评分、不宣称识别精确发质或真实剪发保证。例图与最终生成一致性是主要价值。

共用积分，但按真实成本决定新工具单次扣费，不照搬老照片10积分，也不另造新积分包。技术失败释放积分的逻辑可复用；任务成功但脸部变化/用户不满意不会自动被系统识别，须明确重试与补偿成本，不能承诺无上限免费重做。

用户无需写提示词是独立页面相较现有通用生成页的主要便利，仍须通过结果和实际付费验证；提示词包装本身不是竞争优势。

## 验证与经济性（尚未执行）

先复用现有生成能力评估合法自拍的发型改造，无需先做新页面：建议10张不同光照/发质自拍×3种目标造型，记录脸、肤色、背景是否被无关修改、发型符合程度、延迟与每次成本。样本数量为初步测试设计，不证明市场。真实未授权自拍不使用。

质量先过关，再判断是否增加正式工具页；工具发布前另补用户要求的获客/流量前置资料。若模型需要专业分割或多次生成才能保住脸，重新估算，不以新页面已写好为继续理由。

上线后的关键数据应单独归因：发型入口访问→上传→成功生成→购买；区分既有余额消费与新增购买、旧用户与新流量。共用积分收入只能按透明分摊规则估算，不把每次积分消费当新增收入。

新增经营贡献 = 发型归因净收入 - 模型及重试 - 支付费用 - 获客 - 新增支持/存储等成本；另计研发时间。已有平台减少固定投入，不让获客或模型成本消失。免费用户用完仍需算成本，不直接照搬VocalDock历史免费额度问题和低价包实验。

## 什么情况下才考虑独立

只有当发型有持续独立获客与付款、专门品牌有可验证益处，或用户反复使用原生相机/个人造型库等移动能力时，再评估独立品牌/App。即使未来分品牌，也可研究共享技术底座；但独立账户支付迁移有成本。本地已有TikTomato iOS工程不等于本轮已验证其上线/复用条件。

D-048仍待补证据，作为已有产品扩展候选关联TikTomato，非已存在功能，52项计数不变。没有代码改动、模型调用、安装或发布。
